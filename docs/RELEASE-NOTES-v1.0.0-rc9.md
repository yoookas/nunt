# nunt v1.0.0-rc9

第九个候选版本：dns-01 的传播检查改为以权威服务器为准（这次是真正的失败原因），
反向代理向 Caddy 对齐三处，外加两处界面修正。

## 修复：dns-01 传播检查被递归缓存误导

rc8 之后仍然失败，日志里的应答说明了原因：

```
1.1.1.1:53 = 顶点值 + 泛域名值
223.5.5.5  = 只有泛域名值
8.8.8.8    = 只有泛域名值
```

顶点域和泛域名共用 `_acme-challenge.<zone>`，两个值先后写入。递归解析器会缓存
「该名字只有一条 TXT」的旧应答，而 DNSPod 的 TTL 下限是 **600 秒**，所以它们最长
10 分钟内都不会看到第二条值；我们当时却要求**所有**公共解析器都看到期望值，等待
窗口 5 分钟，于是超时——记录本身没有问题。

现在与 certmagic 一致：

- **先问该 zone 的权威服务器**（CA 校验时查的就是它们），任意一台返回期望值即通过；
- 公共解析器不再参与判定，只在解析不到权威服务器时作为后备（该后备也已按 Caddy
  语义移除：配置了「DNS 解析服务器」的任务改用这些 resolver，否则只查权威）；
- 轮询间隔 5 秒 → **2 秒**（与 certmagic 一致），窗口仍为 5 分钟。

## 更接近 Caddy 的 dns-01 行为

- 签发失败时**撤销挂起的授权**（pending authorizations），避免占用账号的待处理授权
  配额，反复重试不会被 CA 拒绝；已验证的授权保留，下次订单可直接复用；
- 传播检查的 TXT 应答按集合比较，一个名字下多条记录时只匹配「包含期望值」。

## 反向代理

- **`X-Forwarded-*` 信任模型**：默认不信任任何代理，入站值被丢弃并用连接信息重建；
  只有开启 `system.trustProxy` 时才保留客户端链（与 Caddy 的 `trusted_proxies` 语义
  一致，只是粒度暂时是全局开关）。
- **不再周期性刷新响应**（Caddy 默认行为）；SSE 和未知长度响应仍即时下发。
- **新增「最少连接」负载策略**（`least_conn`），按在途请求数选择上游，平手时回退轮询。

## 界面

- 概览统计卡片：值独占一行，不再被启动时间挤压成 `49 …`；
- 顶栏去掉重复的「nunt 管理后台」副标题。

## 升级

换镜像即可；重启后需要重新登录，浏览器强刷一次。

## 验证建议

用真实腾讯云账号再签发一次。成功时日志里应看到每个域名一条
`dns-01 的 TXT 记录已传播`；失败时会列出权威服务器逐个的应答。反向代理方面可以
在 Web 路由里把负载均衡切到「最少连接」验证多上游分流。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc9-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc9 docker compose up -d
```

四个归档（amd64 / arm64 / armv7 / oci）的校验和都在 `SHA256SUMS` 里。
