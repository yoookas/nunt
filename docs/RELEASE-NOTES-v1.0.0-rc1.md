# nunt v1.0.0-rc1

首个公开候选版本。功能面按 1.0 的范围收口；这个 RC 的目的是让真实环境（真实域名、真实 DNS、真实容器）
把剩下的验证跑完，而不是继续加功能。

## 包含什么

- **Web 反代**：监听器 / 路由两层；反向代理、重定向、静态托管；多上游负载均衡（轮询/随机/IP 哈希）
  与被动熔断 + 幂等重试；路径重写；请求/响应头；CORS（预检本地 204）；IP / UA / 国家省份过滤；
  BasicAuth；WebSocket 与 h2c；请求级访问日志
- **端口转发**：TCP / UDP / 同时转发，并发与单 IP 上限、空闲超时、源地址 ACL、上下行流量统计
- **DDNS**：阿里云、腾讯云、Cloudflare、Spaceship、自定义回调
- **证书**：http-01 / dns-01 / tls-alpn-01，泛域名，自动续期，Let's Encrypt staging 开关，
  上传 / 导出，监听器客户端证书（mTLS）
- **WAF**：Coraza + CRS v4，可保护管理面本身
- **管理面**：Argon2id、服务端会话、CSRF、登录限流与锁定、管理端 IP 白名单、
  API Token（只读/读写 scope）、TOTP 双因子与一次性恢复码
- **可观测**：运行日志可配轮转与下载；访问日志落盘（JSONL，按天/大小轮转）、检索、统计、CSV 导出；
  概览页显示证书到期与模块失败；`/metrics`（Prometheus 文本格式，位于鉴权之后）；最近 24 小时请求趋势
- **运维**：定时备份（仅配置 / 密钥 / 证书 / ACME 账号）、`nunt healthcheck` 健康检查子命令
- **容器**：非 root + `cap_net_bind_service`、多架构镜像、OCI 标签、compose 加固参数、
  健康检查与 20 秒停止宽限

## 镜像

不发布到 Docker Hub 或 GHCR；Release 附件是可 `docker load` 的镜像归档，另有 OCI 布局归档：

```sh
docker load < nunt-v1.0.0-rc1-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc1 docker compose up -d
```

`amd64` / `arm64` / `armv7` 各自是单架构归档；`-oci.tar.gz` 三平台合一的 OCI 布局，`docker load` 读不了它
（需要 `ctr images import` 或 podman）。所有归档的校验和汇总在 `SHA256SUMS` 里。

## 这个版本**没有**验证过的（重要）

- **从未对真实的 Let's Encrypt 跑过完整签发与自动续期**：只有单元测试与本地自签证书；
- **DNS 提供商未用真实账号联调**：阿里云、腾讯云、Cloudflare、Spaceship 都有请求级测试，
  但真实 API 的权限与边界行为没有实测；DDNS 与通配符证书都依赖这一层；
- **真机 `docker compose up` 没有用户报告**：镜像构建、健康检查、compose 起栈在 CI 里跑，
  但真实宿主机上的挂载、权限、端口占用仍需自测；
- **浏览器逐页 E2E 缺失**：前端只有 jsdom 挂载冒烟（9 个路由），弹窗交互与视觉布局没有自动化覆盖；
- **没有 24 小时长跑与压测**：只有 600 请求的短时脚本（goroutine 与内存稳定）。

以上五项是 RC 阶段最值得回报的问题来源；遇到任何一项不符合预期，请附日志（`/data/logs/`）与配置片段。

## 已知限制

- 管理面是**单管理员**设计，没有多角色；审计信息只写进程日志；
- **没有告警通道**：证书/续期失败、规则监听失败只在概览页与日志里显示；
- 上游健康检查是**被动熔断**（连续 3 次 5xx 摘除 30 秒），没有主动探测；
- 没有 HTTP/3；没有请求缓存；
- 升级方式就是换镜像，不支持自更新；`config.json` 写入时保留一份 `.bak`。

## 升级与回滚

- 从 `v0.3.0` 升级：直接换镜像并保留数据目录即可，配置文件会自动补齐新增字段的默认值；
- 回滚：换回旧镜像 + **同时回滚数据目录**（新版本会写入 `logs/access/`、可能新增配置字段）；
- 升级前请先做一次备份（设置 → 备份 → 立即备份并下载），归档里包含 `secret.key`，需要自己加密保存。
