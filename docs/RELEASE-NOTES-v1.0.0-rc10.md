# nunt v1.0.0-rc10

第十个候选版本：修掉「添加标签就崩溃」的问题，并让被占用的端口不再静默失败——
监听器会自动停用，由你手动开启。

## 修复：添加标签时页面崩溃

在监听地址、User-Agent、国家/地区里输入内容回车时，页面报
`cannot be rendered outside a collection` 并白屏。原因是 HeroUI 的 `Tag` 属于
react-aria 的集合成员，必须在 `TagGroup` 里使用，而这些字段是普通输入框。

现在改用独立的 `Chip` 组件（带一个小号移除按钮），省份多选也一起修好了。
jsdom 冒烟里加入真实交互：打开监听器表单、输入 `:443` 回车、断言不报错且标签出现；
把组件换回 `Tag` 重新构建，冒烟会复现同样的堆栈并失败。

## 端口被占用：监听器停用，手动开启

之前保存成功但绑定失败只写日志，界面和健康检查都看不出来；把已有监听器改到被占用的
端口时还会先关掉旧地址，站点直接下线。

现在：

- 绑定失败（`address already in use` 等）时，监听器被**自动停用**：`disabled` 写入配置，
  重启和重载都不会再尝试这个端口，日志各一条 ERROR/WARN；
- 模块详情显示 `N disabled`，监听器列表出现「状态」列，用官方 **Switch** 控制启停
  （与路由的启停开关一致）；
- 手动开启时如果端口仍被占用，接口返回 **409** 和「端口仍被占用，监听器保持停用」，
  开关保持关闭；端口释放后再打开即可恢复；
- 挂在这个监听器上的路由在停用期间显示为未激活；
- 删除了此前为绑不上的地址临时开的兜底监听（`127.0.0.1:<随机端口>`）。

## 升级

换镜像即可；重启后需要重新登录，浏览器强刷一次。

## 验证建议

1. 新建一个监听地址指向已被占用的端口，添加并启用一条路由 → 监听器应显示「已停用」；
2. 释放端口后拨动开关 → 监听器恢复、路由变为运行中；
3. 在任意标签字段（监听地址、UA、国家）输入并回车 → 不再崩溃。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc10-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc10 docker compose up -d
```

四个归档（amd64 / arm64 / armv7 / oci）的校验和都在 `SHA256SUMS` 里。
