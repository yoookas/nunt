# nunt v1.0.0-rc27

第二十七个候选版本：概览页的四张卡片并成一行，访问规则的「添加规则」修好了。

**没有配置变更**，升级后不需要重新配置任何规则。

## 概览页

- `系统概览 / 系统资源 / 磁盘 / 服务` 四张卡片排在同一行（宽屏四等分，窄屏 2×2，手机单列）；
- 「系统概览」从横跨整行的标题条变成一张卡片：主机名、版本、运行时长和健康标签，
  上次刷新时间放在卡片右上角，轮询失败时状态标红、时间停住；
- 「服务」改成四行紧凑条目（圆点、名称、主指标、细节），能在 1/4 宽度里完整显示
  Web 服务、端口转发、动态域名和证书；
- 「磁盘」最多显示三个挂载点，其余折叠为「另有 N 个挂载点」；
- 两张请求曲线保持不变。

## 修复：添加规则没有反应

- 点击「添加规则」确实插入了一行，但 `normalizeAccess()` 会把 `value` 为空的条目过滤掉，
  组件重新渲染时这一行立即消失，看起来像按钮没反应；
- 更糟的是旧的 `add()` 会顺手把「其余流量」从允许改成拒绝，于是唯一的可见变化就是它；
- 现在编辑器用 `keepEmpty` 归一化，正在填写的空行会保留，提交时仍会被丢弃，不会写进配置；
- 添加规则不再改动「其余流量」；
- 删掉「不可移动或删除」的提示（行内与表单说明各一处）。

## 验证

- `gofmt` 干净；`go vet ./...`、`go build ./...` 通过；
- `go test ./... -count=1`：22 个包、410 个测试全部通过；
- `npm run build`、`npm run smoke`（10 条路由）通过；
- 概览页与访问规则编辑器用 Playwright 在 1440 宽下截图核对：四张卡片等高成行，
  连续点击两次「添加规则」后新行保留且「其余流量」不变。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc27-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc27 docker compose up -d
```

四个归档（amd64 / arm64 / armv7 / oci）的校验和都在 `SHA256SUMS` 里。
