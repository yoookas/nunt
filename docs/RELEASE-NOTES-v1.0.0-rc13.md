# nunt v1.0.0-rc13

第十三个候选版本：一次完整安全审计后的修复批次，另含 WAF 大请求体处理调整。
没有新增功能页，配置格式不变。

## 安全修复

- **路径规范化**：路由匹配前统一规范化 `//`、`.`/`..`、`\` 等写法。此前
  `//admin`、`/./admin` 之类的路径会绕过 `/admin` 规则上的 BasicAuth、IP/UA
  过滤与 WAF，而 nginx 等上游却会把它归一化成 `/admin`；
- **X-Forwarded-For**：改为取**最右**一条（最近代理追加的客户端地址），客户端
  自己写在左边的值不再能决定 IP 白名单、限流、地理过滤和日志里的地址；
- **修改密码**：当前密码校验接入登录限流， stolen session 不能在线爆破密码；
- **TOTP**：step-up 接口拒绝已用过的验证码（登录此前已经拒绝），同一码不能再
  用来关闭 2FA 或重发恢复码；
- **DDNS 测试**：不再向线上写入 `192.0.2.1` 再删除记录，只校验凭据格式；
- **mTLS**：客户端 CA 解析失败时监听器**拒绝启动**，不再静默降级为不校验；
- **BasicAuth 哈希**：规则 API 不再返回哈希，配置导出打码，导入时自动回填；
- **地址库路径**：配置校验拒绝相对路径、设备文件、FIFO，`/dev/zero` 之类的
  导入不会再拖死请求或让下次启动失败；
- **ACME**：CA 返回的授权必须属于本次申请的域名（通配符接受其基名），避免
  被不诚实的 CA 借 DNS 凭据验证别的域名；
- 运行时限流参数生效、备份/日志下载 `no-store`、带 zone 的 IPv6 对端不再解析
  为 nil、未声明信任代理时不再透传 `X-Real-IP` / `X-Client-IP`。

## WAF：大请求体

- 检查上限从 10 MiB 提到 **256 MiB**，默认仍是 128 KB；
- 上限只决定**检查多少**，不限制能传多大：超过上限的部分照常流式转发，不会 413；
- 每个请求内存最多 1 MiB，超出部分由 Coraza 落临时文件，大上限不再等于大内存
  占用；代价是上限以内的请求体要先缓冲完才转发。

## 行为变化

- `trustProxy=true` 时 XFF 取最右。**单层代理**行为正确；**多层代理/CDN** 会取到
  最近一层代理的地址而不是真实客户端——这类部署建议暂时保持 `trustProxy=false`，
  或等后续的 `trustedProxies` CIDR 配置；
- 「测试 DNS 提供商」不再写记录，按钮文案改为「校验凭据」；
- 开启 mTLS 但 CA 无效的监听器会显示错误并停止，而不是带病运行；
- 规则 API 里 BasicAuth 的密码字段为空表示「保持原密码」，与编辑表单一致。

## 验证

- 新增路径规范化、XFF 取最右、改密限流、mTLS 拒绝启动、地址库路径、ACME 授权
  域名、WAF 内存上限等回归测试；
- `go vet`、全量 `go test ./...`、前端构建与 11 条路由冒烟通过；
- 路径绕过、XFF 伪造、改密爆破、DDNS 测试、BasicAuth 哈希、mTLS、限流参数等
  均在本地实例上实机复现并确认修复。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc13-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc13 docker compose up -d
```
