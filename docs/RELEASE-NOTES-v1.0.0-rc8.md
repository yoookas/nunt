# nunt v1.0.0-rc8

第八个候选版本：dns-01 的两处实现问题一次修完，并清掉了界面上残留的「账户」装饰。

## 修复：dns-01 校验

### 1. TXT 记录被当成单值覆盖（顶点域 + 泛域名）

证书里同时包含 `example.com` 和 `*.example.com` 时，两者的挑战记录名相同
（`_acme-challenge.example.com`），但 TXT 值不同、且必须**同时存在**。

之前每个 DNS 提供商的写入都是「同名同类型只留一条，值不同就改」，第二个授权把第一个
的值覆盖掉了，CA 的二次校验于是报 `No TXT record found`。

现在 TXT 按多值集合处理：值不存在就**新增一条**，删除时只删「名字 + 类型 + 值」都匹配的
那一条。腾讯云、阿里云、Cloudflare、Spaceship 均已修改，A/AAAA/CNAME 仍保持替换语义
（DDNS 需要）。

### 2. 流程对齐 certmagic/acmez

- **先发布全部挑战再开始校验**：三段式（present → accept → wait），保证 CA 开始验证时
  所有答案都已就位；
- **传播检查改问权威服务器**：先确认公共解析器可见，再要求该域的权威 NS 也返回对应值
  （CA 实际查的就是权威服务器，这正是 `secondary validation` 失败的常见原因）；
- **跟随 `_acme-challenge` 的 CNAME**：把挑战委派到另一个 zone 时，记录写到链尾的名字，
  传播检查也盯这个最终名字；
- TXT 应答按集合比较，一个名字下有多条记录时只匹配「包含期望值」。

## 界面

- 首次启动横幅不再打印「管理员账号」；
- 侧边栏去掉品牌块和底部的管理员卡片，只保留导航；
- 顶栏账户区改为单个图标按钮，下拉里的「修改密码 / 退出登录」都带图标。

## 升级

换镜像即可，配置与数据兼容；重启后需要重新登录一次，浏览器强刷一次拿新界面。

## 仍未验证

- 真实 Let's Encrypt 签发（本轮修复直接针对它，请务必用真实账号跑一次）；
- 其他 DNS 提供商的真实账号联调；
- 真机 `docker compose` 长期运行、浏览器 E2E、24 小时长跑。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc8-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc8 docker compose up -d
```

四个归档（amd64 / arm64 / armv7 / oci）的校验和都在 `SHA256SUMS` 里。
