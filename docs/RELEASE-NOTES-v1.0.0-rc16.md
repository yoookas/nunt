# nunt v1.0.0-rc16

第十六个候选版本：修复官方 ip2region 地址库的字段解析错误——省份和城市过滤此前
实际上从未命中。

## 修复：官方地址库字段错位

官方 v4/v6 库的一行是：

```
国家|省份|城市|ISP|国家代码
中国|江苏省|南京市|南京新锋信息|CN
```

旧代码按 `国家|区域|省份|城市|ISP` 读取，于是省份被读成城市、城市被读成 ISP：
国家能匹配，**省份/城市永远匹配不上**，表现就是「IP 列表有效，地址库指定的值无效」。

现在固定按官方格式解析，`Reserved|Reserved|Reserved|0|0` 与 `0` 占位符解析为空记录；
`Record` 中未使用的 `Region` 字段一并删除。

## 诊断改进

- 地址没有地区数据（私有、回环、保留地址）时，访问日志的拒绝原因显示
  `reason=geo-no-data`，不再只是 `no-match`；
- 三个表单的地区提示补充：私有/回环地址没有地区数据；服务在反向代理后面时
  需要开启信任代理，否则匹配到的是代理地址。

## 升级说明

- **不需要重新上传地址库**，库文件不变，只是读取方式变了；
- 旧格式（`国家|区域|省份|城市|ISP`）不再支持——当前部署使用的是官方库，
  保留兼容代码没有意义，已经删除。

## 验证

- 用官方 v4/v6 库实测：`114.114.114.114` 解析为 中国 / 江苏省 / 南京市 / 南京新锋信息；
- 过滤实测：`江苏` 放行 114.114.114.114、拒绝 223.5.5.5；`南京` 同样命中；
  `中国` 命中 IPv6 `2400:3200::1`；
- 私有地址 `127.0.0.1` 返回 403 且日志为 `geo-no-data`（预期：库中无地区数据）；
- 全量 `go vet` / `go test ./...`、前端构建与 11 条路由冒烟通过。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc16-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc16 docker compose up -d
```
