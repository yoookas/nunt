# nunt v1.0.0-rc26

第二十六个候选版本：访问日志从一张大表拆成 Web 访问和端口转发两张表，各自有自己的
字段、筛选与导出，行高压缩一半。

**没有配置变更**，升级后不需要重新配置任何规则。

## 访问日志：一张表拆成两张

- 日志页现在是 **运行日志 / Web 访问 / 端口转发** 三个平级 Tab，不再有混合视图；
- 删除了端口转发页内嵌的日志面板，也删除了路由编辑器里的日志 Tab——同一份日志只有
  一个入口；
- 两张表各自筛选：Web 有「状态」筛选，端口转发**没有**（转发记录没有 HTTP 状态），
  关键字提示分别是「路径 / 域名 / UA」和「目标 / 规则 / 结果」；
- 表头随来源变化：`规则 / 连接 / 结果 / 连接时长` 取代 `站点 / 规则 / 请求 / 状态 / 结果 / 耗时`，
  Web 与转发共用同一套视觉语言但不共用同一组列名。

## 字段变多，行变矮

每行现在只占一行（58px → **34px**，手机 40px），同屏可见记录大约翻倍。原来的第二行
信息（域名、UA、地区、↑↓ 字节）拆成了独立列，完整记录仍然点开抽屉看。

| Web 访问 | 端口转发 |
|---|---|
| 时间 · 来源 · 站点/规则 · **域名** · 请求 · **上游** · 状态 · **说明** · 客户端 IP · 地区 · 大小 · 耗时 | 时间 · 来源 · 规则 · 连接 · **协议** · 结果 · **原因** · 客户端 IP · 地区 · **上行** · **下行** · 连接时长 |

- 「说明」显示 WAF 动作、拒绝原因或代理错误，出错时标红；
- 列声明改成描述符数组，表头和数据行不再各写一遍，加字段只需改一处；
- 响应式断点从只认 `xxl`（1600px）改成 `lg` / `xl`，1440px 的窗口即可看到此前要
  1600px 才出现的列；
- 手机端保留 时间 / 来源 / 请求 / 状态 四列并收进视口，不再横向溢出切掉状态列。

## CSV 导出跟随来源

- 端口转发导出 17 列：时间、规则、监听、协议、客户端 IP、国家、省份、城市、目标、结果、
  拒绝原因、错误、耗时、请求字节、响应字节、总字节、消息；
- Web 导出 28 列：在原有字段基础上保留来源、请求 ID、域名、方法、路径、状态、UA、WAF 动作；
- 导出测试改为按表头名取列，不再依赖列号，列序调整不会再让公式注入测试假通过。

## 修复

- **Web 访问表看不到 `source=waf` 的记录**：拆表后该 Tab 固定传 `source=web`，而管理后台
  自身被 WAF 拦截的记录仍单独写作 `source=waf`，这些记录于是从界面上消失了。现在
  `source=web` 同时匹配两种来源（被拦截的依然是一次 HTTP 请求），Web 导出保留「来源」
  列以区分两者。

## 验证

- `gofmt` 干净；`go vet ./...`、`go build ./...` 通过；
- `go test ./... -count=1`：22 个包、410 个测试全部通过；
- `npm run build`、`npm run smoke`（10 条路由）通过；
- 两张表用 Playwright 在 1440×900 与 390×844 下截图核对，行高、列宽与溢出均符合预期。

## 镜像与校验

```sh
docker load < nunt-v1.0.0-rc26-amd64.tar.gz
NUNT_IMAGE=nunt:v1.0.0-rc26 docker compose up -d
```

四个归档（amd64 / arm64 / armv7 / oci）的校验和都在 `SHA256SUMS` 里。
