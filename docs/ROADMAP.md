# 路线图（单管理员部署）

> 本文是当前唯一的计划口径。范围假设：**只有一名管理员**，不追求多租户/多角色；
> 项目定位是自托管的边缘网关（反代 / 转发 / DDNS / 证书 / WAF / 日志）。
> 细则（TOTP 的接口与验收）见 [TOTP-PLAN.md](TOTP-PLAN.md)。

## 0. 现状判断

| 维度 | 状态 |
| --- | --- |
| 功能面 | Web 反代 / 端口转发 / DDNS / ACME / WAF / 访问日志 / 容器 均已具备 |

## S1 · 发布后立刻：把「没验过」补上

价值最高、不写业务代码。做完这一档，产品可信度从「看起来完整」变成「确实能用」。

| # | 事项 | 成本 | 验收 |
| --- | --- | --- | --- |
| 1 | 真机 `docker compose up` 全流程 | 0.5 天 | 挂载/权限/端口/日志/健康检查/重启保持配置 |
| 2 | ACME 对真实 Let's Encrypt 签发 + 自动续期 | 0.5 天 | 一张正式证书签发、热加载、把剩余天数改到阈值触发一次续期 |
| 3 | DNS 提供商真实联调（DDNS + dns-01） | 0.5 天 | 记录在服务商控制台可见；错凭据的失败路径也有明确提示 |
| 4 | 浏览器逐页 E2E（Playwright 或手工清单） | 0.5~1 天 | 8 个页面 + 登录/改密 + 表单校验无运行时报错 |
| 5 | 24h soak + 一次压测 | 1 天 | RSS/goroutine/连接数前后对比无泄漏；P99 与错误率有数字 |

> 第 2、3 项需要你有真实域名和 DNS 账号；第 5 项可以在自己机器上跑一夜。

## S2 · 安全与运维（单人最需要的兜底）

| # | 事项 | 成本 | 为什么排这里 |
| --- | --- | --- | --- |
| 1 | **TOTP + 恢复码 + 前端二维码** | ✅ 完成 | 两段式登录、10 枚一次性恢复码、种子加密、二维码本地绘制；接口与验收见 [TOTP-PLAN.md](TOTP-PLAN.md) |
| 2 | 证书/续期状态在概览页做显眼 | 0.5 天 | 告警通道暂缓时的折中：续期失败、≤7 天、规则监听失败直接上首页 |
| 3 | 定时备份（data 目录打包 + 保留份数） | ✅ 完成 | 归档仅含配置/密钥/证书/ACME 账号，默认 24h × 7 份，可在设置页改 |
| 4 | 上游健康检查 / 熔断 + 一次幂等重试 | ✅ 完成 | 连续 3 次 502/503/504 摘除 30 秒（全挂时仍会尝试），GET/HEAD/OPTIONS 失败自动换节点重试一次 |

**依赖**：TOTP 与其它项互不依赖；建议按 1 → 2 → 3 → 4 做，TOTP 单独开分支。

## S4 · 明确不做（至少这一版）

| 项 | 原因 |
| --- | --- |
| RBAC / 多角色 | 单管理员，API Token 的 scope 已覆盖自动化场景 |
| 审计日志独立落盘 | 「谁改的」只有一个答案；进程日志里的 `admin action` 够用 |
| i18n / OpenAPI / forward-auth / OIDC | 单用户、中文场景，收益接近零 |
| HTTP/3 | 需要引入 `quic-go`，与现有依赖约束冲突，家庭场景收益小 |
| 自动更新 | 升级路径是换镜像；自更新会引入下载校验与回滚的一整套问题 |
